# direct-crm — CLAUDE.md

«CRM Директа» — `direct-crm.aicex.club`. **Хозяин — Богдан, РОП** (в офисе hq2: `HEAD_CONTENT.sales.products`
в `apps/hq-office/agent-content.js`; работает с ней агент «Переписки» `chats`). Источник переписок — ChatPlace, где
работает ИИ-менеджер Директа (аккаунты @ilia.paliy и @paliy_ilya) и Telegram-боты. CRM сама в Директ не отвечает —
только когда человек пишет из неё.

- `server.mjs` — HTTP (статика `public/` + `/api/*`) и два независимых цикла: синхронизация раз в `SYNC_SEC` (60 с) и разбор Claude
  (сразу следующая пачка, если что-то разобрал, иначе через 30 с) — долгий разбор не задерживает новые сообщения. Claude — таймаут 90 с,
  один повтор. `/api/health` — без входа: чатов, сообщений, разобрано / ждут разбора, `backfill`, модель и `status` (этап каждого цикла,
  прогресс, последняя ошибка). Выкладка в конце печатает `health` и хвост журнала контейнера.
- `lib/chatplace.mjs` — ChatPlace через его MCP-сервер (JSON-RPC по HTTP, своя `user-agent`, иначе 403). Подключение —
  сервер `chatplace` из mcp-config офиса (`HQ_RUNNER_MCP_JSON` → `CHATPLACE_MCP_JSON`). Инструменты: `chats_list`,
  `chats_get`, `chats_messages` (чтение), `chats_open` / `chats_send_message` / `chats_close` (действия менеджера).
- **ChatPlace стоит за Cloudflare и банит частые запросы** (HTTP 429, error 1015 — так и вышло при первой загрузке): клиент шлёт не чаще
  раза в 1,5 с (`gapMs`), ответ 429 сразу обрывает проход (`rateLimited`), цикл синхронизации молчит 10 мин, потом вдвое дольше до 2 ч
  (`status.sync.pausedUntil`). Каждый запрос во время бана его продлевает — не ускорять и не перезапускать в цикле.
- `lib/sync.mjs` — проход: (1) `chats_list` (новые сверху) до водяного знака (`meta.watermark`; первый проход — `BACKFILL_DAYS` назад),
  только список; (2) сообщения не более чем `pullsPerPass` (40) чатов, у которых последнее сообщение новее загруженного — очередь из базы,
  поэтому чат с ошибкой добирается в следующем проходе; профиль (username) — не больше 10 за проход; сообщения — страницами до первого известного. Ничего не удаляет: CRM — архив переписок.
  Добор истории (`backfill`): каждый проход продолжает `chats_list` от самой старой загруженной переписки (`backfillPages` = 2 страницы, только список),
  пока не дойдёт до `BACKFILL_DAYS` назад (`meta.backfill_done`); если ChatPlace не листает дальше — останавливается, а не крутится.
  Ответ из CRM сохраняется сразу с id `crm-…`; когда ChatPlace вернёт его, id заменяется настоящим (без дублей).
- `lib/analyze.mjs` — Claude (`CRM_MODEL`, по умолчанию `claude-opus-5-5`, effort low, структурированный JSON) читает
  чат, когда в нём новые сообщения и он молчит `quietSec` (90 с — ИИ ChatPlace успевает ответить): `priority`
  (hot «Готов купить» / human «Нужен человек» / normal / low), `stage` (new/warm/hot/customer/lost — этап, поставленный
  вручную, не перезаписывает), `source` (кодовое слово), `summary`, `next_step`, `ai_score` 1–5 и `ai_issues` (типы — `ISSUE_TYPES`).
  Ошибка разбора чата — повтор не раньше чем через 30 мин.
- **Почти реальное время в пределах лимита ChatPlace.** Бюджет — один запрос в 1,5 с (~40 в минуту, `cp.rate()` в `/api/health`).
  Проход раз в 15 с (`SYNC_SEC`; 3 с, пока догружается история): 1 запрос списка + сообщения изменившихся чатов (не больше 10)
  + не больше одного запроса каталога. Новое сообщение появляется в CRM через 15–30 с; на странице — «обновлено N с назад».
  Вебхук `http_request` из цепочек ChatPlace не используем: он есть только внутри цепочек (не у ответов ИИ-агента) и на PRO.
- `lib/catalog.mjs` — цепочки ChatPlace и вопросы ИИ-агента, по одному запросу за проход: боты (раз в сутки), список цепочек бота
  (раз в час), детали каждой активной цепочки — сообщения, сколько людей дошло, кнопки с нажатиями и CTR (раз в час, копия за день
  в `funnel_days` — прирост за период), вопросы без ответа из базы знаний ИИ (раз в 15 мин). `mark(message)` размечает переписку:
  кодовое слово, нажатая кнопка, шаг какой цепочки. `funnels(db, days)` — вкладка «Цепочки».
- `lib/learn.mjs` — «Обучение ИИ»: черновик ответа Claude на вопрос, на который ИИ-агент не ответил (или «пропустить», если не по
  теме), ответ уходит в базу знаний ChatPlace (`ai_agent_knowledge_base_add_answer`) **только по кнопке человека** и пишется в журнал;
  разбор ошибок ИИ за 7/30 дней (правила «если … то …», недостающие ответы, что проверить в цепочках) — `meta.ai_review`.
- Квалификация в разборе каждой переписки: `lead_score` 0–100, `interest`, `objection`, `contact`; в «Воронке» — распределение,
  главные возражения и «что нажимали и писали люди» (по разметке `mark`).
- `lib/api.mjs` — очередь (`view=queue`: готовые купить и «нужен человек», плюс все, кто ждёт ответа больше 10 мин;
  кроме «разобранных» до нового сообщения клиента), все / мои, переписка, действия `take` / `release` / `reply` /
  `stage` / `priority` / `review` / `refresh`, отчёты `/api/stats?days=` (воронка, источники, оценки ИИ, ошибки, по дням,
  медиана ответа менеджера). Каждое действие — строка в `events` (кто и что).
- `lib/auth.mjs` — вход по логину и паролю: `bogdan` (`CRM_BOGDAN_PASSWORD`), `ilia` (`CRM_OWNER_PASSWORD`), или
  `CRM_USERS_JSON`. Подписанная кука `dcrm` на 30 дней, 10 неверных попыток с адреса — пауза 15 мин.
- `lib/db.mjs` — `node:sqlite` (Node ≥ 22.13), файл `DATA_DIR/crm.sqlite`: `chats`, `messages`, `events`, `meta`.
- `public/index.html` — одна страница без сборки: Очередь · Все · Мои · Воронка · Качество ИИ; на телефоне — нижние вкладки.
- `check.mjs` — проверка с поддельными ChatPlace (MCP по HTTP) и Claude; идёт в каждом деплое (`npm run check`).

Деплой: `.github/workflows/deploy-direct-crm.yml` → `deploy/server.sh` (образ `aicex-direct-crm:<релиз>`, контейнер в сети
`edge`, данные `/opt/direct-crm/data`, копия базы перед каждым запуском в `/opt/direct-crm/backup`, 7 последних,
блок `/opt/edge/sites/direct-crm.caddy`). Локально: `npm install && CRM_BOGDAN_PASSWORD=x npm start` → `:8795`
(без `CHATPLACE_MCP_JSON` показывает, что уже есть в базе).
